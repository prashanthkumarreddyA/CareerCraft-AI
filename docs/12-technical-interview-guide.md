# 12 · Technical interview guide

Everything below is based on what is in the repository. If asked about something not built (Phase 7,
emails, DOCX, CI), say it is planned or out of scope.

## 2-minute introduction

> "CareerCraft AI is a MERN-style application that tailors one master resume to a specific job
> description without fabricating anything, and then tracks the application.
>
> The user uploads their resume PDF once. I extract it with pdf.js into structured JSON and store the
> original privately in Cloudinary. When they paste a job description, Gemini extracts the
> requirements in one structured-JSON call, but the classification and the match score are decided
> by JavaScript rules against numbered evidence from the resume – a technology only counts if the
> resume names it, so Express.js never becomes NestJS.
>
> For tailoring, Gemini proposes rewrites of the summary and bullets; a claim checker compares every
> proposal with the cited evidence – technologies, numbers with units, seniority words, ownership,
> professional identity, even the kind of action – and blocks or flags anything unsupported. The user
> reviews each change, approves, and the PDF is generated by a layout engine I wrote in Phase 1 that
> reproduces the original Word layout line for line. Before storing it, the PDF is read back and must
> equal the approved content.
>
> Phase 6 adds an application tracker with a controlled status pipeline, Kanban board, interviews,
> follow-ups, analytics and CSV export. It's React on Netlify, Express on Render, MongoDB Atlas,
> Cloudinary and Gemini, with 210 backend tests."

## Problem statement

Tailoring resumes by hand is slow and breaks formatting; generic AI writers invent skills and metrics.
The goal: keep the original layout and make every statement traceable to the master resume.

## Architecture in one picture

Browser (React SPA) → Express API (auth, validation, rules, PDF engine) → MongoDB Atlas,
Cloudinary (private files), Gemini (structured JSON). Diagrams: [02-system-architecture.md](02-system-architecture.md).

## Technical challenges worth telling

1. **Reproducing a Word layout** – the PDF could not be edited (subset fonts, no reflow), so I measured
   it and re-implemented Word's paragraph model (line height from font metrics, keep-with-next,
   widow/orphan control). Validation showed 81/81 identical lines with sub-point deviations.
2. **A bug only visible to the eye** – pdf-lib's font subsetting dropped glyph outlines; text
   extraction passed but pages were blank. Fixed by shipping pre-built Latin subsets.
3. **AI hallucination** – solved by architecture, not prompting alone: grounding with evidence ids,
   verbatim checks, a narrow taxonomy, the claim checker, a repair round, human review, and a PDF round trip.
4. **Gemini structured output limits** – the JSON Schema with min/max constraints was rejected
   ("too many states"), so the schema sent to the model is simplified while zod still enforces all limits.
5. **Retired models** – a model could be listed but refuse generation; the provider validates models,
   falls back, and the smoke test checks configuration.
6. **Concurrency without transactions** – local MongoDB is standalone; I embedded histories and used a
   `revision` field for optimistic concurrency so every change is one atomic update.
7. **A browser-only bug** – CORS didn't allow PATCH, which supertest could not catch; a preflight test
   now covers it.

## Important engineering decisions

| Decision | Why |
|---|---|
| AI proposes, rules decide | scores and resume facts must be explainable and testable |
| One structured AI call per analysis | lower cost/latency, consistent answer |
| Score computed in JavaScript with fixed weights | transparent, reproducible, not an "ATS score" |
| Concrete technologies: named or missing | related ≠ experienced; avoids inflated matches |
| Master resume immutable; tailored versions store a snapshot | history stays valid; no accidental overwrite |
| Freeze approved content with a SHA-256 hash | the PDF provably matches what was approved |
| Private raw Cloudinary assets + signed URLs | resumes are personal data |
| JWT in Authorization header, tokenVersion revocation | frontend and API on different sites; logout must invalidate tokens |
| Embedded sub-documents + revision | atomic updates, no transactions needed |
| Dependency injection of AI and storage | fast, deterministic tests without external services |

## AI hallucination prevention (short answer)

"The model never gets the final say. It cites evidence ids that must exist; keywords must appear in
the JD; only aliases count as the same skill; every proposed sentence goes through a claim checker
for technologies, names, numbers and units, quantities, seniority, ownership, identity and action type;
failures get one repair round and are otherwise blocked; uncertain meaning changes need an explicit,
audited human confirmation; and the final PDF is re-extracted and compared with the approved content."

## PDF generation challenges

Subset fonts, absolute text positioning, Calibri licensing (→ Carlito, metric-compatible), page-break
rules, 2-page limit, unprintable characters, and proving equality (round-trip extraction + template
comparison). The engine is frozen and its backend copy is tested for byte identity.

## MongoDB schema decisions

Five collections, all owned by `userId`. Large flexible payloads (resume JSON, analysis results,
change lists) are `Mixed` and validated by zod at the boundary. Applications embed their histories,
interviews and follow-ups (bounded arrays). Indexes start with `userId`. Unique indexes enforce one
master per user and unique version numbers per analysis.

## Authentication and security

bcrypt, HS256 JWT with token version, ownership checks returning 404, strict zod validation, CORS
allow-list, rate limits (per IP and per user), helmet, upload magic-byte check, private storage with
signed URLs and integrity hashes, CSV formula protection, logs without content. Known gaps:
localStorage token, no refresh tokens or account deletion ([08](08-security-and-privacy.md)).

## Deployment

Netlify (static SPA with SPA redirect), Render (Node web service, health check, env validation at
start), Atlas, Cloudinary, Gemini. Render's free tier cold starts are handled by a health-polling
"waking" state in the UI.

## Scalability considerations

- The API is stateless except for in-memory rate limits → a shared store would be needed for
  multiple instances.
- PDF extraction/rendering is CPU-bound in-process → move to a worker/queue at scale.
- AI calls are slow (seconds) → a job queue with status polling would free request threads.
- Dashboard aggregates per request in memory (fine for thousands of applications per user);
  pre-aggregation or MongoDB aggregation pipelines at larger scale.
- Embedded arrays are bounded (20 interviews, 50 follow-ups, 500 status events).

## Interview questions and answers

### React and frontend

1. **How is authentication state managed in React?**
   An `AuthContext` stores `{ token, expiresAt, user }` in state and `localStorage`. On load it verifies
   a stored session with `/auth/me`; a 401 clears it, a network error keeps it (server may be waking up).
   The axios instance gets a token getter and a 401 handler through `configureAuth`.

2. **How do protected routes work?**
   `RequireAuth` renders a spinner while verifying, redirects signed-out users to `/login` with the
   original path in router state, otherwise renders `<Outlet/>`. `GuestOnly` does the opposite for
   login/register.

3. **Why no Redux?**
   Server data is page-scoped and fetched per page; only auth and backend health are global, and two
   contexts cover them. Adding a store would add complexity without a shared-state problem to solve.

4. **How do you handle concurrent edits in the UI?**
   Each mutation sends `expectedRevision`. A 409 triggers a reload. On the application detail page,
   actions are queued so quick clicks each use the revision returned by the previous request.

5. **How is the Kanban drag-and-drop implemented without a library?**
   Native HTML5 drag events: `dragstart` records the card, columns call `preventDefault` in `dragover`
   only for allowed targets (from `allowedStatuses` returned by the API), `drop` calls the status
   endpoint. A "Move to…" select covers keyboard and touch, and a toast offers undo.

6. **How is the PDF preview shown securely?**
   The PDF is fetched with the Bearer token as a Blob, turned into a temporary `blob:` URL for an
   iframe, and revoked on unmount. No storage URL reaches the page.

7. **How do you deal with Render cold starts?**
   A shared health hook polls `/api/health` with short timeouts and retries for up to 90 s, showing a
   "Waking server…" state instead of failing.

### Node.js and Express

8. **How are errors handled?**
   Services throw `ApiError` with status, code and a safe message; Express 5 forwards async rejections
   to one error handler that also maps parser, multer, Mongoose and MongoDB connectivity errors into
   one JSON envelope. Only 5xx are logged.

9. **Why an app factory (`createApp({ storage, ai })`)?**
   Tests can inject fake storage and a scripted AI, so the full HTTP stack is tested without network
   calls, and production uses Cloudinary and Gemini.

10. **How is input validated?**
    zod strict schemas per route via `validateBody`; unknown keys are rejected, strings cleaned and
    bounded; error details include paths but never values.

11. **How are uploads handled?**
    multer memory storage (no disk), 5 MB limit, MIME allow-list, then a `%PDF` signature check, then
    extraction. Nothing is stored until extraction and schema validation pass.

12. **What happens if Cloudinary succeeds but MongoDB fails?**
    Compensation: the uploaded file is deleted again. On replacement the record update is conditional
    on the previous file id so concurrent replacements cannot both win.

13. **How do rate limits differ?**
    General per-IP limit; stricter per-IP limit for login/register; per-user limits for uploads/PDF
    generation and AI calls, which protect quota and cost.

14. **How does the server avoid starting misconfigured in production?**
    `checkEnvironment()` lists missing required variables (names only) and the process exits.

### MongoDB

15. **Why embed interviews and follow-ups instead of separate collections?**
    They belong to one application, are bounded, and are always read with it; embedding gives atomic
    single-document updates without transactions.

16. **How do you prevent lost updates?**
    A `revision` counter: updates filter on `{ _id, userId, revision: expected }` and `$inc` it; no match
    means either 404 or 409.

17. **How is a unique version number per analysis guaranteed under concurrency?**
    A unique compound index `{ userId, jobAnalysisId, versionNumber }`; insertion retries on a
    duplicate-key error.

18. **How is data isolation enforced?**
    Every query includes `userId`; foreign and malformed ids both give 404; linked records are looked up
    with the same user's id; tests check cross-user access on every router.

19. **Why store analyses as snapshots?**
    An analysis must stay explainable even after the resume changes; the stored resume hash marks it
    stale instead of silently recomputing.

20. **How is deletion of linked records handled?**
    An analysis or tailored version referenced by an application (now or in its link history) cannot
    be deleted (409). Deleting an application deletes only the application.

### AI integration

21. **Why one structured-JSON call instead of several prompts?**
    Lower latency and cost, and a consistent view of the JD; deterministic code does the rest.

22. **How do you validate AI output?**
    JSON mode with a response schema, then `JSON.parse`, then zod. Invalid answers are retried once per
    model, then reported as `AI_INVALID_RESPONSE`.

23. **What does the AI decide and what not?**
    It extracts keywords, importance and responsibilities and drafts wording. Matches for technologies,
    the score, ordering, claim validity, approval and PDF checks are code.

24. **How do you stop "Express.js" from counting as "NestJS"?**
    The taxonomy distinguishes aliases (same thing) from related technologies. Only aliases or more
    specific parts count; related technologies are shown as context with zero credit and cannot be
    written into the resume (`GAP_KEYWORD`, not overridable).

25. **How are retries designed?**
    Exponential backoff with jitter for 429 (when the wait is short), 5xx, timeouts and network errors,
    all within a total time budget; then fallback models; auth or safety errors are not retried.

26. **How do you protect privacy when calling Gemini?**
    Only professional content goes out: no contact details, company or school names, locations or the
    PDF; emails/URLs/phones and the name are redacted inside text; logs never contain prompts.

27. **How is prompt injection handled?**
    The JD and evidence are marked as untrusted data inside tags, the system instruction says never to
    follow instructions in them, and any effect is limited because code verifies every output.

### PDF processing

28. **Why not edit the original PDF?**
    Subset fonts lack many glyphs, Word positions each line separately (no reflow), and pdf-lib cannot
    edit content streams – so the layout was re-implemented.

29. **How do you know the generated PDF matches the template?**
    Phase 1 validation compared all 81 lines geometrically. In production every PDF is read back with
    the extractor and must equal the approved content, with the same fonts, sizes, margin and headings
    as the master rendered by the same engine.

30. **Why Carlito?**
    It is metric-compatible with Calibri (same widths, so identical line breaks) and open-licensed, so
    it can be deployed.

31. **How is the 2-page limit enforced?**
    The layout engine runs without writing a PDF to report page count, overflow and growing paragraphs
    during review; approval and PDF generation reject more than 2 pages. Fonts and spacing are never shrunk.

### Security

32. **How does logout work with stateless JWTs?**
    Tokens carry a `tv` claim; logout increments the user's `tokenVersion`, and verification compares
    them, so all earlier tokens stop working.

33. **What is CSV formula injection and how is it handled?**
    Spreadsheet apps execute cells starting with `=`, `+`, `-`, `@`. Such cells are prefixed with `'`
    and every cell is quoted.

34. **Why are storage ids never sent to the browser?**
    Files are only reachable via backend-checked streams or short-lived signed URLs; exposing ids adds
    no value and leaks structure.

### System design

35. **How would you scale this to many users?**
    Shared rate-limit store, background workers for AI calls and PDF rendering, queue + polling, CDN for
    the SPA, Atlas scaling, and possibly pre-computed dashboard aggregates. The API is already stateless.

36. **What would you improve next?**
    Refresh tokens and a CSP, account deletion, CI with tests on every push, committed browser tests,
    code splitting, and Phase 7 (interview preparation) – see [13-future-roadmap.md](13-future-roadmap.md).
